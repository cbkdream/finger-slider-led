## 1. 개요

웹캠으로 손을 인식해서 엄지와 검지 사이 거리로 슬라이더 값을 바꾸고, 그 값으로 LED 밝기를 조절하는 미션이다.

출장 중이어서 아두이노 보드가 없어 출력 원리를 소프트웨어로 시뮬레이션했다. LED는 p5 화면 가운데에 가상 LED로 그렸다. 슬라이더 값(0~255)에 따라 LED의 투명도(alpha)와 크기가 바뀐다. 아두이노 쪽 코드와 회로는 Wokwi 시뮬레이터에서 확인했다.

동작 순서

```

     → 슬라이더(0~255) → "B:값" 전송 → 아두이노(가상) → LED 밝기
```

## 3. 구현 내용

### 3.1 손 인식

수업 예제처럼 `ml5.handPose()`로 모델을 불러오고 `detectStart(video, gotHands)`로 인식을 시작했다. 손을 찾을 때마다 `gotHands()`가 호출되어 `hands` 배열이 바뀌고, `draw()`에서는 이 값을 가지고 점과 뼈대를 그린다.

사용한 점

| 번호 | 위치 | 용도 |
|---|---|---|
| 0 | 손목 | 기준점 |
| 4 | 엄지 끝 | 거리 계산 |
| 8 | 검지 끝 | 거리 계산 |
| 9 | 중지 뿌리 | 손바닥 길이 |
| 12 | 중지 끝 | 주먹 모드 확인 |

### 3.2 주먹 모드

손을 펴고 있을 때도 값이 계속 바뀌면 불편해서, 수업 예제의 `isGrabMode()`를 그대로 사용했다. 손목~중지 끝 거리가 손바닥 길이(손목~중지 뿌리)보다 짧으면 중지를 접은 것으로 보고, 이때만 슬라이더를 움직인다. 중지를 펴면 값이 그대로 유지되고 마우스로 슬라이더를 움직일 수 있다.

### 3.3 거리 → LED 값

엄지-검지 거리를 손바닥 길이로 나눠서 비율로 만들었다. 이렇게 하면 손이 카메라에 가깝든 멀든 같은 손 모양이면 비슷한 값이 나온다.

```js
let s = round(100 * (v / p)) - 15;      // v: 엄지-검지, p: 손바닥
s = constrain(s, 0, 100);
return round(map(s, 0, 100, 0, 255));   // LED 값 0~255
```

수업 예제는 0~100이었는데 LED 값(PWM)에 맞추려고 `map()`으로 0~255로 바꿨다. 슬라이더 범위도 0~255로 바꿨다.

### 3.4 슬라이더 움직임 보정

손 인식 값이 조금씩 떨려서 목표값과의 차이 중 20%씩만 움직이게 했다. 그런데 이렇게 하면 슬라이더가 정수 단위라서 목표에 거의 다 와서 멈추는 문제가 있었다(자료 19쪽, 50 → 90일 때 88에서 멈춤). 이동량이 0.5보다 작아지면 반올림 때문에 제자리로 돌아오기 때문이다. 차이가 3보다 작으면 바로 목표값으로 맞추도록 한 줄을 추가했다.

```js
let next = c + 0.2 * (v - c);
if (abs(v - c) < 3) next = v;
slider.value(next);
```

### 3.5 가상 시리얼 / 가상 아두이노

보드가 있으면 `serial.send()`로 보낼 부분을 함수로 대신 만들었다. 슬라이더 값을 바로 LED에 쓰지 않고 `"B:값"` 문자열을 만들어서 `virtualArduino()` 함수에 넘기고, 이 함수가 값을 꺼내 LED 값을 정한 뒤 `"PWM:값"`을 돌려준다. Wokwi에 넣은 아두이노 코드와 같은 형식이다.

- 값이 바뀔 때만 보내고, 50ms보다 자주 보내지 않게 했다. (실제 9600bps에서 매 프레임 보내면 밀릴 수 있어서)
- `B:`로 시작하지 않는 문자열은 무시하고, 값은 0~255로 제한했다.
- 화면 오른쪽 아래에 보낸 값과 받은 값을 표시했다.

### 3.6 가상 LED

`drawVirtualLed()`에서 LED 모양(머리, 몸통, 다리)을 그리고, 값에 따라 아래처럼 바꿨다.

- 투명도: `fill(r, g, b, 값)` → 0이면 안 보이고 255면 완전히 보임
- 크기: 지름 70px ~ 110px
- 빛 번짐: 주변에 반투명 원 여러 개 + `drawingContext.shadowBlur`

꺼진 회색 LED를 먼저 그리고 그 위에 색을 겹쳐 그려서 값이 0일 때도 LED 모양은 보이게 했다. 아래쪽에는 듀티비에 맞는 PWM 파형도 같이 그렸다.

| 값 | 0 | 64 | 128 | 191 | 255 |
|---|---|---|---|---|---|
| 듀티비 | 0% | 25% | 50% | 75% | 100% |
| 크기(px) | 70 | 80 | 90 | 100 | 110 |

## 4. Wokwi 회로

```
D9 ── 220Ω ── LED(+)    LED(-) ── GND
```

`wokwi/sketch.ino`는 시리얼로 한 줄씩 받아서 `B:값` 형식이면 `analogWrite(9, 값)`을 하고 `PWM:값`을 출력한다. `readStringUntil()`은 기다리는 동안 멈출 수 있어서 글자를 하나씩 모아 줄바꿈이 오면 처리하는 방식으로 짰다.

시리얼 모니터에 `B:0`, `B:64`, `B:128`, `B:255`를 입력해서 LED 밝기가 바뀌는 것을 확인했다.

## 5. 실행 방법

p5
1. 데모 실행 링크를 Chrome으로 열거나, p5.js 웹 에디터에 `p5` 폴더의 세 파일을 넣고 실행한다.
2. 카메라 권한을 허용하고 모델이 로딩될 때까지 기다린다.
3. 중지를 접은 상태에서 엄지와 검지를 벌리거나 오므린다.

Wokwi
1. Wokwi 회로 링크를 열고 실행 버튼을 누른다.
2. 시리얼 모니터에 `B:값`을 입력한다.

## 7. 고찰

- 처음에는 손이 조금만 흔들려도 LED가 깜빡거렸는데 20%씩 움직이게 하니 훨씬 부드러워졌다. 대신 정수 반올림 때문에 목표값에 못 가는 문제가 생겨서 따로 처리해야 했다.
- 거리를 손바닥 길이로 나누는 방법 덕분에 카메라와의 거리가 달라져도 값이 크게 바뀌지 않았다. 다만 손을 기울이면 손바닥이 짧게 보여서 값이 올라갔다.
- 출장 중이라 보드 없이 가상으로 만들었지만, 슬라이더 값을 바로 쓰지 않고 문자열로 보내고 받는 과정을 거치게 해서 나중에 보드가 생기면 전송 부분만 바꾸면 되도록 했다.
- PWM 파형을 같이 그려 보니 LED 밝기가 켜져 있는 시간의 비율이라는 것을 이해하기 쉬웠다.
- 개선할 점: 지금은 첫 번째 손만 사용하는데, 양손으로 LED 두 개를 따로 조절해 보고 싶다. 어두운 곳에서는 인식이 불안정해서 신뢰도가 낮으면 값을 바꾸지 않도록 하는 것도 필요해 보인다.
